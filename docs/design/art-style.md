## **INTRODUCTION**

This document serves as the definitive reference for the visual style of Jones in the Fast Lane. It outlines the artistic direction, standards, and specifications for all visual elements of the game.

### **Project Overview**

Jones in the Fast Lane is a remake of Sierra On-Line's 1991 life simulation game. This modernized version maintains the nostalgic charm of the original while enhancing visual fidelity and user experience for contemporary platforms.

### **Art Style Philosophy**

Our approach blends nostalgic pixel art with modern design sensibilities. We're creating a:

* **Modernized retro aesthetic** that honors the original while appealing to today's players  
* **Clean, readable interface** that works across multiple platforms  
* **Character-driven visual storytelling** that showcases personality and humor  
* **Cohesive world** with consistent visual language across all game elements

## **VISUAL IDENTITY**

### **Core Visual Pillars**

1. **Modern Retro** \- Not purely pixel art, but incorporating pixel-inspired elements with modern techniques  
2. **Vibrant & Bold** \- Bright colors, distinctive silhouettes, and eye-catching compositions  
3. **Humorous & Expressive** \- Characters and environments that convey personality and wit  
4. **Accessible & Clear** \- Visual hierarchy that ensures information is easily understood

### **Art Style References**

* **Primary Inspiration:** Original Jones in the Fast Lane (Sierra, 1991\)  
* **Modern Pixel Art:** Stardew Valley, Papers Please, Unpacking  
* **UI/UX Design:** Persona 5, Two Point Hospital  
* **Visual Humor:** The Sims series, Overcooked

## **CHARACTER DESIGN**

### **Character Style**

Characters should be designed with:

* Semi-realistic proportions with slight stylization  
* Distinctive silhouettes that are recognizable at small sizes  
* Expressive faces with exaggerated features for clarity  
* Clean, readable clothing and accessories

### **Player Characters**

Create 4 distinct player character options with:

* Gender diversity  
* Cultural diversity  
* Age diversity (young adult to middle-aged)  
* Body type diversity  
* Distinctive fashion styles

Each character should have:

* Idle pose  
* 4-direction walk cycle  
* Work animation  
* Study animation  
* Shopping animation  
* Eating animation  
* Victory/defeat poses  
* Barrel costume version (when clothes wear out)

### **NPC Design**

#### **Employer NPCs**

Employer NPCs should visually communicate:

* Their workplace environment  
* Level of authority  
* Personality type (stern, friendly, etc.)  
* Professional field

#### **Service NPCs**

Service NPCs include:

* Store clerks  
* Bank tellers  
* University staff  
* Landlords

Each should have:

* Appropriate uniform or attire  
* Service-oriented pose  
* 1-2 simple animations

### **Character States**

All characters should have visual representations for:

* Normal state  
* Hungry state  
* Tired state  
* Happy/successful state  
* Disappointed/failure state  
* Worn-out clothing state

## **ANIMATION GUIDELINES**

### **Character Animations**

* Frame rate: 12-24 fps depending on action  
* Animation style: Keyframe with minimal tweening  
* Walk cycles: 8-12 frames per direction  
* Action animations: 6-10 frames  
* Reaction animations: 4-8 frames  
* Idle animations: 4-6 frame loops with occasional special cycles

### **UI Animations**

* Transitions: 0.2-0.3 seconds for standard transitions  
* Easing: Ease-out for entering elements, ease-in for exiting  
* Feedback: 0.1-0.2 second effects for button presses  
* Loading: Simple looping animation (3-5 frames)  
* Celebrations: More elaborate animations for achievements (10-15 frames)

### **Animation Principles**

Focus on these key animation principles:

* Anticipation: Telegraph major actions  
* Squash & Stretch: Add life to character movements  
* Follow-Through: Create natural motion endings  
* Exaggeration: Emphasize important actions  
* Timing: Vary speeds for realistic feel

### **Technical Requirements**

* All assets delivered in PNG format unless specified  
* SVG source files provided for vector elements  
* Layered source files (PSD, AI) included for all composite assets  
* Assets named according to project conventions: `[type]_[name]_[state]_[size].png`  
* Texture atlases for related elements to minimize draw calls

## **APPROVAL PROCESS**

### **Asset Review Workflow**

1. **Concept Phase**: Rough sketches and direction  
2. **First Draft**: Initial colored versions  
3. **Revision Round**: Addressing feedback  
4. **Final Approval**: Sign-off before implementation  
5. **In-Game Review**: Final check in game context

### **Feedback Guidelines**

When providing feedback:

* Reference specific parts of the art style guide  
* Be specific about what needs to change  
* Provide visual references when possible  
* Consider technical limitations  
* Focus on consistency with overall style

### **Version Control**

* Maintain version numbers for all assets  
* Date all revisions  
* Archive previous versions  
* Document major changes  
* Use consistent file naming: `[asset]_v[version]_[date].png`
